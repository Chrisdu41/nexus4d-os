# Sprint 6 Acceptance Tests

## Cockpit
- [ ] Une mission possède un état explicite.
- [ ] Une mission bloquée expose la cause du blocage.
- [ ] La prochaine action est toujours visible.
- [ ] Le score qualité n'est jamais présenté comme prédiction de performance.

## Client Workspace
- [ ] Les faits stables sont séparés des expériences.
- [ ] Les learnings sont séparés des données brutes.
- [ ] Le contexte chargé peut être daté et sourcé.
- [ ] Les données privées ne sont pas nécessaires au package Cowork.

## Cowork Pilot
- [ ] Un workflow complet peut être exécuté séquentiellement.
- [ ] L'orchestrateur ne prétend pas lancer des agents parallèles inexistants.
- [ ] Les informations bloquantes sont demandées avant production.
- [ ] La mission se termine avec KPI, prochaine action et proposition de mémoire.

## Release
- [ ] Une checklist v0.6 existe.
- [ ] Le pilote possède un protocole reproductible.
- [ ] Les erreurs peuvent être classées par sévérité et couche responsable.
