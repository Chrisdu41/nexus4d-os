# Sprint 5 — Acceptance Tests

## Library
- [ ] chaque type de bibliothèque documente son contexte d'usage ;
- [ ] aucun exemple n'est présenté comme règle universelle ;
- [ ] les niveaux de preuve sont visibles ;
- [ ] les promotions Example → Pattern exigent des signaux documentés.

## Playbooks
- [ ] chaque playbook respecte `00-playbook-contract.md` ;
- [ ] une hypothèse est explicite avant production ;
- [ ] les spécialistes sont identifiés ;
- [ ] les gates peuvent bloquer l'exécution ;
- [ ] le Definition of Done inclut mesure et apprentissage.

## Scorecard
- [ ] le score ne prétend pas prédire la performance ;
- [ ] les hard stops bloquent un livrable même avec un score global élevé ;
- [ ] vérité, preuve et testabilité sont notées séparément.

## End-to-End Demo
- [ ] le contexte est explicitement fictif ;
- [ ] aucun faux verbatim n'est créé ;
- [ ] les hypothèses sont traçables ;
- [ ] l'expérience ne contient aucune fausse métrique ;
- [ ] le learning reste à faible confiance ;
- [ ] le learning simulé ne peut pas être promu dans une mémoire client réelle.

## Sprint Definition of Done
Sprint 5 est acceptable si un lecteur peut suivre le chemin complet :

`Context → Mission → Specialists → Hypothesis → Playbook → Experiment → Scorecard → Learning`

sans ambiguïté entre donnée réelle, simulation et hypothèse.
